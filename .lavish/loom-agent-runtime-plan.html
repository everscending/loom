Technical implementation proposal · 15 August 2026

Make the coding agent replaceable.

Loom’s tracker state machine is already mostly agent-neutral. The coupling lives at the execution edge: command construction, prompt transport, permissions, trust, native event streams, usage limits, model names, and setup artifacts. Put one deep module at that seam; keep the scheduler ignorant of vendor CLIs.

Recommendation: add a provider-neutral agent.sh module with Claude and Codex adapters, migrate every Loom-created session to its three-command interface, and normalize both native JSONL streams before the rest of Loom sees them. Keep Claude as the compatibility default; enable Codex only after the shared security and conformance suite passes.

02 · seam

Give callers one semantic agent interface.

The deletion test is decisive: if this module disappeared, vendor checks and flag logic would reappear in wave launch, lane spawn, merge chaining, bootstrap, rendering, liveness, retro, tests, and documentation. That is a deep module earning its seam.

Current

Callers construct vendor commands

  • The wave must know Claude flags and placeholder syntax.
  • spawn-lane inspects the executable basename.
  • Telemetry readers parse a vendor’s native stream directly.
  • Bootstrap owns a single vendor’s policy artifact and trust store.
Target

Callers describe an agent run

  • Role, cwd, brief, model intent, and execution profile are inputs.
  • The adapter chooses CLI, prompt channel, flags, and environment.
  • The adapter emits Loom’s canonical JSONL schema.
  • Provider setup and readiness are queried through the same module.

External interface · scripts/agent.sh

Three operations; all provider complexity stays behind them.

doctor

Read-only preflight. Returns one JSON document with provider, binary/version, authentication, policy/trust readiness, model support, writable roots, network capability, and actionable failures.

run

Runs one semantic role — wave, implementation, gate, merge, or probe — from a prompt file in a cwd with an optional model intent. Streams canonical Loom JSONL to stdout and preserves the provider process exit status.

install-policy

Idempotently creates or verifies the selected provider’s repo-resident policy artifacts. Refuses to overwrite a differing hand-edited surface without --force.

Canonical stream

One JSONL schema

Use a small vocabulary: session start, assistant progress, command/tool progress, usage, limit, error, and session end. Include provider plus requested/resolved model metadata. Preserve unknown native event kinds as ignorable provider events, so a CLI upgrade cannot silently break parsing.

Cost semantics

Nullable dollars

Codex authenticated through ChatGPT may have tokens but no defensible per-run dollar price. Retro must report tokens and cost unavailable, not convert API list prices into a fictional subscription cost.

Model semantics

Provider-native first

Keep wave_model, lane_model, and rework_model as provider-native strings in the first release. Stop pre-creating Claude-only escalation labels; create model::<value> lazily. Semantic cross-provider tiers can follow if hot-switching providers becomes a real requirement.

04 · implementation sequence

Six phases, each independently shippable.

Do not rewrite the scheduler and the agent transport in one step. Characterize the current Claude behavior, land the seam with two adapters, and move one class of callers at a time.

Characterize the contracts before moving them

Capture representative Claude and Codex JSONL fixtures; enumerate wave/lane command shapes, prompt paths, exit codes, rate-limit cases, auth/trust failures, and policy behavior. Add an adapter conformance test section that can run entirely on fake CLIs.

Exit: fixtures fail against a deliberately incomplete adapter.

Introduce the agent module and both adapters

Add scripts/agent.sh, private drivers under scripts/agents/, and provider-specific normalizers. Set agent_provider: claude as the compatibility default. Implement doctor, run, and install-policy without changing existing launch callers yet.

Exit: Claude and Codex pass the same black-box interface tests.

Migrate wave and lane launchers

Make _launch_wave, production lane spawns, and chain-merge call the semantic module. Add spawn-agent-lane; retain raw spawn-lane -- <cmd> only as internal plumbing/test seam. Delete executable-basename detection, CLI flag injection, @brief knowledge, and vendor model parsing from tick.sh.

Exit: no production path outside an adapter constructs claude or codex.

Move filesystem plumbing out of the model

Add a deterministic worktree-preparation verb so scheduling waves no longer need broad write access to the parent directory merely to create sibling worktrees. Keep env copying, base fetch, path validation, and setup in machinery. This lets the Codex wave run with narrow writable roots instead of granting every sibling repo.

Exit: the wave can orchestrate under its least role policy.

Normalize telemetry and setup

Switch rendering, progress counting, usage-limit classification, and retro to canonical events. Delegate policy generation and readiness checks from bootstrap to the adapter. Replace Claude-specific config/docs with agent_provider and the logical unattended execution profile; accept the old permission_mode only as a deprecated Claude compatibility alias.

Exit: native provider JSON is never read outside its adapter.

Documentation, migration, and opt-in rollout

Update SKILL.md minimally to show semantic spawn commands. Put provider detail in a new maintenance reference. Make README installation/invocation agent-neutral, explicitly point briefs at docs/agents/issue-tracker.md instead of relying on CLAUDE.md, and document Codex skill installation plus non-interactive prerequisites. Ship Codex opt-in; flip no defaults during this proposal.

Exit: a third fake provider is added by one adapter + fixtures, with no scheduler edits.

06 · safety and compatibility

Security is part of the adapter interface.

“The command starts” is not compatibility. Loom’s hard denials and unattended behavior must survive the provider swap, or the adapter refuses before spending a session.

HIGH · CODEX PROJECT RULES ARE EXPERIMENTAL

Do not declare Codex GA on syntax alone.

Verify that project rules are loaded in a trusted worktree and that forbidden commands are blocked under the exact non-interactive invocation. If stable enforcement is unavailable, keep Codex beta and require an externally hardened runner rather than weakening Loom’s constitution.

HIGH · WORKSPACE-WRITE DOES NOT COVER SIBLING WORKTREES

Avoid granting the whole parent directory.

Move worktree creation into deterministic machinery, then grant each session only its worktree and Loom state/scratch. Explicitly enable network only for roles that need tracker, forge, dependency, or probe access.

MEDIUM · NATIVE EVENT SCHEMAS WILL CHANGE

Unknown events must degrade visibly.

Adapters preserve an unknown-event marker, conformance fixtures pin required events, and doctor reports tested version ranges. Rendering may degrade; scheduling and exit classification must not silently change.

MEDIUM · PROVIDER SWITCHES REPRICE MODELS

Make the provider explicit.

Never auto-select whichever binary happens to be on PATH. agent_provider is read-only config, surfaced by resolve-config, recorded on spawn events, and required in every diagnostic.

MEDIUM · PROMPT CONTEXT DIFFERS

Pass required context explicitly.

The wave brief points at Loom’s own SKILL.md; lane briefs point at the canonical tracker declaration and include their work. Vendor instruction files remain useful repo context, but Loom correctness does not depend on one filename being auto-loaded.

LOW · HISTORICAL LEDGERS NAME CLAUDE

Do not rewrite evidence.

Keep dated defects, proposals, and incident histories intact. The acceptance grep excludes historical ledgers and adapter-specific files; only active core instructions and machinery must become neutral.

07 · verification and rollout gates

Prove substitution without running a real Loom build.

The repository’s maintenance rule forbids a costly real build as verification. Use fake CLIs, captured native streams, disposable git fixtures, and one narrowly-scoped opt-in CLI smoke test.

Required automated gates
  • Both adapters pass the same black-box conformance cases: prompt, cwd, model set/omitted, success, crash, limit, auth failure, policy refusal, and paths with spaces.
  • Hard-denial planted violations fail for each adapter; tests verify the actual policy evaluator, not generated source text.
  • Canonical fixtures render the same semantic transcript and drive the same progress/limit decisions.
  • snapshot → plan output is byte-equivalent across provider selections except explicit provider/model metadata.
  • The full tick-test.sh suite passes twice.
Release gates
  • Claude remains the default and its existing behavior is characterized before refactoring.
  • Codex is opt-in via agent_provider: codex.
  • A disposable repo smoke test runs one no-op wave and one no-op lane through the real installed CLI; it does not touch a real tracker or start a build.
  • Adding a third fake adapter changes only the adapter registry, one adapter directory, and fixtures.
  • Active core files contain no vendor CLI tokens outside provider selection/dispatch.

Compatibility definition: Codex support is complete only when a fresh session can reconstruct and advance the same tracker-resident build, under the same failure policy and hard denials, with no Claude files or commands required.

08 · decisions

Two scope choices; both have recommendations.

Neither choice blocks the interface design. They determine how much migration lands in the first implementation.

Recommend now

One provider per repo/build

Add one agent_provider setting used by waves and all lane roles. The interface retains a role argument, so provider-per-role routing can be added later without changing callers. Mixed-provider builds add pricing, model, policy, and diagnosis complexity without current evidence that Loom needs them.

Recommend staged

Provider-native models first

Keep current model config keys and treat their values as native to the selected provider. Remove fixed Claude labels now; postpone universal model tiers until there is a real need to switch providers mid-build. This gets Codex compatibility without inventing a lowest-common-denominator model taxonomy.
